# AI 问答智能搜索设计

## 目标

在现有“AI 团务助手”对话页面中增加一个简洁的“智能搜索”开关。开启后，系统在保留本班知识库检索的同时，调用 Tavily 与百度检索互联网公开信息，并将整理后的内容及可追溯引用交给 DeepSeek 生成回答。

本次不新增独立搜索页面，不展示搜索引擎选择器，不增加深度思考、推荐问题、检索步骤面板或其他模式按钮。

## 用户体验

- 输入框工具栏只新增一个带地球图标的“智能搜索”按钮。
- 按钮是可切换状态：关闭时为白底中性色，开启时为浅绿色底、绿色边框并显示对勾。
- 每次发送消息时，以按钮当时的状态决定该条消息是否联网；发送后切换按钮不会影响正在进行的请求。
- 默认关闭，避免普通对话产生不必要的联网请求与 Tavily 配额消耗。
- 开启后通过现有状态提示区域显示简短状态，例如“正在智能搜索互联网”；不新增常驻搜索过程面板。
- 回答仍在现有消息区域流式输出。互联网引用与知识库引用共用现有来源区域，但按来源类型采用适合的展示字段。
- 底部只保留一条简短免责声明，不显示推荐问题、检索数量或网站标签。

## 总体架构

采用“统一搜索服务 + 两个提供商适配器”的结构：

1. `TavilySearchProvider` 调用 Tavily Search API，作为主要互联网检索来源。
2. `BaiduSearchProvider` 调用百度搜索并解析公开结果，作为中文网页补充来源。
3. `WebSearchService` 并发调用可用的提供商，将不同返回格式归一化为统一结果，随后去重、排序并限制输入给模型的内容长度。
4. 现有对话流接口根据请求中的 `web_search_enabled` 决定是否调用 `WebSearchService`。
5. 现有知识库检索与互联网检索相互独立；任一分支失败不会阻断另一分支或最终回答。

不引入 LangGraph。当前对话链路是清晰的 FastAPI 流式编排，增加一个完整 Agent 框架会扩大改动面，但不会为当前单开关、单轮检索需求带来必要收益。搜索服务保留明确接口，未来若迁移到 LangGraph，可直接包装为工具节点。

## 搜索结果模型

统一结果 `WebSearchResult` 包含：

- `title`：网页标题。
- `url`：最终网页地址。
- `snippet`：与问题相关的摘要或正文片段。
- `published_at`：可选发布时间。
- `provider`：`tavily` 或 `baidu`。
- `score`：提供商分数或本地归一化排序分数。

返回前执行以下处理：

- 按规范化 URL 去重，移除跟踪参数与片段标识。
- 同一标题、相同域名且摘要高度相似的结果合并。
- Tavily 的相关性分数优先；百度结果按原始顺序补充。
- 权威部门、共青团组织、教育部门和高校官方域名在分数接近时优先。
- 最终最多向模型提供 8 条结果，并对每条摘要设置长度上限，控制上下文成本。

## 请求与流式协议

现有消息请求增加布尔字段：

```json
{
  "question": "2026 年高校主题团日有哪些最新要求？",
  "web_search_enabled": true
}
```

缺省值为 `false`，保持对已有客户端的兼容。

沿用现有 SSE 事件：

- `status`：增加 `web_searching`、`web_search_warning` 阶段。
- `sources`：一次返回知识库与互联网来源的统一数组。
- `content`、`message`、`done`、`error`：保持现状。

统一来源对象增加 `type` 字段：

- 知识库来源：`type: "knowledge"`，保留 `filename`、`heading`、`page`。
- 互联网来源：`type: "web"`，包含 `title`、`url`、`domain`、`provider`，不伪造页码。

来源标签在同一回答中连续编号：知识库使用“资料1”等标签，互联网使用“网页1”等标签。模型提示词要求使用完全一致的标签引用。

## 检索与生成流程

1. 保存用户消息和流式中的助手消息占位。
2. 读取最近十条完整历史消息，并处理追问查询补全。
3. 非寒暄问题继续执行本班知识库检索。
4. 当 `web_search_enabled=true` 且不是寒暄消息时，并发执行 Tavily 与百度搜索。
5. 将知识库片段和归一化网页结果分别组装到系统提示词，明确区分“班级资料”和“互联网公开信息”。
6. 要求模型优先依据权威、时效明确的来源回答；存在冲突时说明差异，不自行裁定校级口径。
7. 流式生成回答并保存正文及统一来源对象。

## 提供商行为

### Tavily

- 使用环境变量 `TAVILY_API_KEY`。
- 通过官方 HTTP API 或官方 Python SDK 调用；实现时优先选择与项目现有 `httpx` 依赖一致的 HTTP 调用，避免仅为单接口增加 SDK。
- 默认执行适度深度搜索并请求有限结果，不抓取与问题无关的长正文。
- 未配置密钥时视为该提供商不可用，不导致聊天失败。

### 百度

- 通过公开搜索结果页获取标题、跳转链接和摘要。
- 设置明确的 User-Agent、连接超时、总超时和结果数上限。
- 页面结构变化、验证码或访问限制均作为可预期失败处理。
- 百度只作为补充来源，不承诺稳定性，也不绕过验证码或反爬限制。

## 错误处理与降级

- 两个提供商均成功：合并、去重后使用。
- 仅一个成功：使用成功结果，不向用户显示阻断性错误。
- 两个均失败：发送 `web_search_warning`，继续使用知识库或通用能力回答，并明确说明本次未能取得联网资料。
- Tavily 未配置密钥：百度仍可工作；状态信息指出 Tavily 未配置，但不泄露配置值。
- 单次提供商请求采用短超时，整体搜索设置总时间上限，避免长期占用流式连接。
- 用户取消生成时，取消尚未完成的搜索及模型流，并按现有逻辑保存已产生内容。

## 前端改动范围

- `frontend/src/views/AiCenterView.vue`
  - 增加本地布尔状态 `webSearchEnabled`。
  - 在现有附件按钮与发送按钮之间加入“智能搜索”切换按钮。
  - 发送时把状态快照传给 API 方法。
  - 来源渲染根据 `type` 分支：知识库显示文件位置，网页显示标题、域名和可安全打开的链接。
- `frontend/src/api/conversations.ts`
  - 扩展 `Source` 联合类型。
  - `streamQuestion` 增加 `webSearchEnabled` 参数及请求字段。
- `frontend/src/styles/main.css`
  - 添加智能搜索按钮的关闭、开启、焦点和移动端样式。

不修改侧边栏、顶部导航、空状态推荐内容和会议附件流程。

## 后端改动范围

- 新增 `backend/app/web_search.py`：统一模型、URL 归一化、结果合并和搜索服务。
- 新增 `backend/app/search_providers/tavily.py` 与 `baidu.py`：提供商适配器。
- 修改 `backend/app/config.py`：Tavily 密钥、搜索超时、结果数量及总开关。
- 修改 `backend/app/routers/conversations.py`：请求字段、并发检索、SSE 状态、统一来源及持久化。
- 修改 `backend/app/ai.py`：扩展提示词构造，使其接收知识库与网页上下文。
- 如百度 HTML 解析需要，优先使用现有依赖；仅在标准库无法可靠满足时增加轻量解析依赖。

## 安全与隐私

- Tavily API Key 只从后端环境变量读取，不返回前端、不写日志。
- 只把当前搜索查询发送给搜索提供商，不发送完整聊天历史、本班知识库原文、用户身份或上传文件。
- 前端网页链接仅允许 `http`、`https`，并使用新窗口安全属性。
- 搜索结果属于不可信外部内容；系统提示明确要求忽略网页中的操作指令，只提取与用户问题有关的事实。
- 不把互联网内容标记为校内正式依据，始终保留正式文件核实提示。

## 测试与验收

后端测试覆盖：

- 请求缺省或关闭智能搜索时不调用任何互联网提供商。
- 开启后 Tavily 与百度均被调用，结果正确归一化、去重与限量。
- 任一提供商超时或报错时正常降级。
- 两个提供商均失败时仍能进入回答生成并发送警告状态。
- 提示词中的来源标签与 SSE `sources`、数据库保存内容一致。
- API Key 和聊天历史不会进入搜索请求或日志。

前端测试与构建检查覆盖：

- 按钮可通过鼠标和键盘切换，具有 `aria-pressed` 状态。
- 开启与关闭样式清晰，控件触达尺寸不小于 44 像素。
- 每次请求传递发送瞬间的开关值。
- 知识库与网页来源分别正确显示；危险协议链接不可点击。
- 桌面和窄屏布局不溢出，现有附件与发送操作不受影响。

验收标准：页面只出现一个新增的“智能搜索”入口；开启后可获得带有效网页引用的回答；任何单一搜索服务异常都不会导致 AI 问答整体不可用。
